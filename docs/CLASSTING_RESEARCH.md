# 클래스팅(Classting) 벤치마크 조사 → ClassRing 설계 노트

> 조사 방법: OpenRouter API(`perplexity/sonar-pro`, 웹 검색 결합 모델)로 2026-09 기준 공개 자료를 질의해 정리한 뒤,
> 각 항목을 ClassRing 구현 범위로 귀추(abduction)했다. 아래 내용은 **공개 자료 기반 추정**이며,
> 실제 클래스팅의 내부 구조와 다를 수 있다. (반박 가능성을 열어 둔다.)

## 1. 클래스팅의 핵심 구조 — 한 문장 요약

클래스팅은 **"학급 단위 소셜 피드"** 위에 **"학교 운영 도구(알림장·과제·출석·설문)"** 를 얹고,
최근에는 **"AI 학습 진단·분석"** 을 결합한 3층 구조다.

```
┌──────────────────────────────────────────────┐
│ 3층  AI 러닝 · 학습분석 대시보드 · AI 보조교사(Jello) │  ← 2024~ 강화
├──────────────────────────────────────────────┤
│ 2층  알림장 · 과제 · 출석 · 설문 · 캘린더 · 쪽지     │  ← 운영 도구
├──────────────────────────────────────────────┤
│ 1층  클래스 피드(공지·사진·댓글·반응) · 역할·권한     │  ← 소셜 기반
└──────────────────────────────────────────────┘
```

핵심 통찰: **모든 기능이 "클래스(학급)"라는 단일 컨테이너에 귀속**되고, 그 안에서 **역할(교사/학생/학부모)** 이
권한을 결정한다. 이것이 Google Classroom(과제 중심)이나 카카오톡 단톡방(메시지 중심)과 다른 점이다.

## 2. 기능 목록 (조사) ↔ ClassRing 구현 매핑

| 영역 | 클래스팅 (조사 결과) | ClassRing 구현 | 비고 |
|---|---|---|---|
| 클래스 소식/게시판 | 카드형 피드, 공지·사진·댓글·반응 | ✅ 홈 통합 피드 + 클래스별 피드, 좋아요·댓글·고정 | 유형 필터 탭 |
| 알림장 | 가정 전달 사항, 확인/회신 | ✅ 체크리스트 렌더링, 학생/학부모 "확인" 버튼, 교사용 확인 현황표 | 학생·학부모 분리 집계 |
| 과제 | 생성·제출·채점 상태 | ✅ 마감 D-day, 제출률 바, 학생 제출 모달, 교사 채점(점수·피드백) | AI 피드백 초안 버튼 |
| 출석 | 출결 관리 | ✅ 날짜별 출석/지각/결석/공결, 전원 출석, 30일 출석률 | 학부모는 자녀만 열람 |
| 설문 | 의견 수렴 | ✅ 선택지 투표, 실시간 비율 바, 마감 시각 | 재투표 허용 |
| 사진앨범 | 활동 사진 공유 | ✅ 앨범 게시물(데모는 이모지 타일) + 확대 보기 | 업로드는 서버 필요 |
| 쪽지/채팅 | 1:1 소통 | ✅ 스레드형 쪽지, 안 읽음 수, 구성원에서 바로 쪽지 | |
| 캘린더 | 일정·마감 | ✅ 월간 달력, 학급/평가/행사 + 과제 마감 자동 반영 | |
| 알림 | 이벤트 푸시 | ✅ 파생 알림(새 글·미확인 알림장·마감 임박·댓글·제출·쪽지) | 상태에서 계산, 저장 X |
| 학부모 연동 | 자녀 활동 확인 | ✅ 자녀-보호자 연결, 자녀 미제출/출석 표시 | |
| 초대/참여 | 클래스 코드 | ✅ 초대 코드 참여, 교사의 클래스 생성, 학생 추가 | |
| AI 보조교사(Jello) | 수업 준비 지원, 학습 순서 추천 | ✅ "링고": OpenRouter API 연결, 알림장/과제/피드백/안내문 초안, 스트리밍 | BYOK 키 |

## 4. UI/UX 특징 (조사) → 디자인 결정

- **밝은 배경 + 브랜드 그린 포인트** → `--brand: #10b981`, 회색 `#f3f5f7` 바탕, 흰 카드.
- **카드형 피드가 중심** → 모든 게시물은 동일한 카드 골격(헤더·본문·유형 블록·푸터)으로 통일, 유형별 블록만 교체.
- **모바일 우선 "한눈에"** → 760px 이하에서 사이드바 → 하단 탭바, 우측 레일 숨김, 달력은 점(dot) 표시.
- **교사용은 대시보드 성격** → 출석 탭 상단 통계 4칸, 과제 제출률 바, 알림장 확인 현황표.
- 폰트: Pretendard(CDN) → 시스템 한글 폰트 폴백.

```
#/                    홈 피드 (모든 클래스 통합, 유형 필터, 작성기)

#/class/:id/letter    알림장     #/class/:id/assignment  과제
#/class/:id/album     앨범       #/class/:id/attendance  출석
```

## 6. OpenRouter 연동 설계

- 엔드포인트: `POST https://openrouter.ai/api/v1/chat/completions` (OpenAI 호환), `GET /api/v1/models`.
- 인증: 사용자가 마이페이지에 입력한 키를 `localStorage` 에만 저장(BYOK). 서버를 거치지 않으므로 키가 저장소나 배포 서버에 남지 않는다.
- 헤더: `Authorization: Bearer`, `HTTP-Referer`, `X-Title: ClassRing` (OpenRouter 앱 랭킹 식별용).
- 스트리밍: `stream: true` SSE 파싱, `: OPENROUTER PROCESSING` 주석 라인 무시, `[DONE]` 종료.
- 컨텍스트 최소화: 시스템 프롬프트에는 이름·역할·소속 클래스·다가오는 일정·최근 게시물 제목만 포함. 학생 제출물은 교사가 "AI 피드백" 버튼을 눌렀을 때만 해당 1건을 전송.
- 키가 없으면 **데모 모드**로 규칙 기반 초안을 반환해 흐름을 체험할 수 있다.
- 모델 슬러그 접미사 `:online`(웹 검색), `:nitro`(속도), `:floor`(최저가), `:free`(무료 엔드포인트)를 직접 입력해 활용 가능.

## 7. 다음 단계 (미구현 · 우선순위 순)

1. **백엔드**: `data.js` 의 스토어 계층을 REST/GraphQL 호출로 치환 (인증, 파일 업로드, 푸시 알림).
2. **AI 진단·학습분석**: 문항 은행 + 간단한 IRT/CAT 근사 → 학생별 취약 개념 대시보드 → PDF 리포트.
3. **실시간**: 쪽지·알림을 WebSocket/SSE로.
4. **접근성**: 키보드 포커스 트랩(모달), ARIA live 영역(토스트), 명도 대비 재점검.
5. **i18n**: 문자열 사전 분리(현재 한국어 하드코딩).
